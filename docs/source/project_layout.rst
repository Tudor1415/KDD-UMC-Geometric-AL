Project layout
==============

The repository keeps installable source code under ``src`` and supporting
artifacts at the top level.  The listing below highlights the directories that
matter for the new ball-tree implementation.

.. code-block:: text

   repo/
   |-- src/
   |   |-- gal/                # Legacy GAL package (active learning stack)
   |   |-- trees/              # New n-ary ball-tree builders (this work)
   |   |-- utils/              # Geometry, MEB, and partition helpers
   |   `-- __init__.py
   |-- configs/               # Default configs (Python dict modules)
   |-- tests/                 # Pytest suites for builders and helpers
   |-- docs/                  # Sphinx documentation project
   |-- scripts/               # Command-line entry points & benchmarking tools
   |-- datasets/              # Raw transactional datasets
   |-- mined_rules/           # Pre-mined rule CSVs
   |-- matrices/              # Rule-item matrices produced by preprocessing
   |-- benchmark_outputs/     # Logs and plots generated by experiments
   `-- sota/                  # External baselines for comparison studies

Configuration files
-------------------

``pyproject.toml``
    Declares the package metadata, build system, and optional extras such as
    ``docs`` (installs Sphinx + theme) and ``dev`` (testing utilities).

``README.md``
    High-level orientation, installation steps, and quick-start commands.

``docs/source/*.rst``
    ReStructuredText sources for the documentation, including the
    ``ball_tree_builders`` page that explains the new constructors.

Generated artefacts
-------------------

* ``benchmark_outputs/`` receives CSV snapshots from long-running experiments.
* ``scripts/plots`` produces publication-style figures from those CSV files.
* ``docs/_build`` and ``.pytest_cache`` appear after building docs or running
  tests; both are excluded from version control.
