# RQ1 — Experimental Design (Clean, Structured Markdown)

> **Goal.** Compare **Ball-tree BnB** (proposed) against **Random Sampling** and **Dual kd-tree BnB** (NeurIPS’00 template) for finding *central (near-center) pairs* faster and more reliably, as (i) candidate set size grows and (ii) computational budget varies.

---

## 1) Research Question

**RQ1.** Do **ball-tree branch-and-bound (BnB)** searches identify **central (near-center) query pairs** faster and more reliably than strong alternatives (**Random sampling**, **Dual kd-tree BnB à la NeurIPS’00**) as:

* (i) the candidate set size grows, and
* (ii) the computational budget varies?

---

## 2) Exact Objective (What We Optimize)

Given points $\{x_i\}_{i=1}^n \subset \mathbb{R}^d$ and a center $c \in \mathbb{R}^d$, define the **distance from $c$** to the pair’s mid-hyperplane:

$$
d(i,j)=\frac{\left|\langle c,\ x_i-x_j\rangle-\tfrac12(\|x_i\|^2-\|x_j\|^2)\right|}{\|x_i-x_j\|},\quad i\ne j.
$$

**Oracle optimum (per dataset & center):**

$$
d^\star=\min_{i<j} d(i,j).
$$

We consider **exact** $d(i,j)$ (no surrogates).

---

## 3) Methods Compared

1. **Random Sampling (baseline)**
   Uniformly sample unordered pairs $(i,j), i<j$, until the budget is exhausted; track the best-so-far $d(i,j)$.

2. **Dual kd-tree BnB (NeurIPS’00 “TwoPoint” template)**

   * **Tree:** mrkd-tree (kd-tree + cached stats + AABB).
   * **Traversal:** dual-tree over node pairs with **exclusion/subsumption** rules using objective-specific **LB/UB**.
   * **Leaf–leaf:** compute exact $d(i,j)$ for pairs.

3. **Ball-tree BnB (proposed, greedy disjoint)**

   * **Tree:** disjoint balls; standard center–radius splits.
   * **Traversal:** best-first on **LB** with tight geometric bounds; non-redundant node-pair visitation; leaf–leaf triggers exact $d(i,j)$.

> **Priority rule (BnB):** best-first by **lower bound (LB)**.
> **Stopping:** continue until certified optimality (BnB completed) for the time-normalization protocol; anytime traces are recorded along the way.

---

## 4) Anytime Metric (Single Score, Two Budgets)

Define the **anytime score** at budget $B$:

$$
\boxed{\text{A@B}=\min\!\left(1,\ \frac{d^\star}{d_B}\right)},\quad d_B=\min\{d\text{ observed within budget }B\}.
$$

* Higher is better; **1.0 means optimal** (equal to oracle).
* We plot **two curves** per method:

  * **A\@time (A\@t)** vs normalized wall-clock time.
  * **A\@calls (A\@m)** vs normalized **objective-call** count (exact $d(i,j)$ evaluations that were **not pruned**).

---

## 5) Budgets & Checkpoints

### 5.1 Time Budget (wall-clock)

* For each dataset/center $(R,c)$, run **both BnB methods to completion**; repeat timing **$r$** times.
* Let:

  $$
  T_{\max}=\max\{\text{recorded total times of the two BnB methods across repeats}\}.
  $$
* Evaluate **A\@t** at **20 checkpoints**:

  $$
  t_k \in \{0.05,0.10,\dots,1.00\}\cdot T_{\max}.
  $$
* **Random sampling** runs until $T_{\max}$; log best-so-far at the same $t_k$.

### 5.2 Objective-Call Budget

* Total unordered pairs:

  $$
  P_{\max}=\frac{n(n-1)}{2}.
  $$
* Evaluate **A\@m** at **20 checkpoints**:

  $$
  m_k \in \{0.05,0.10,\dots,1.00\}\cdot P_{\max}.
  $$
* **Objective call** = computing **exact $d(i,j)$** (only when not pruned).

> **Normalization ensures dataset-comparable curves** across runs and methods.

## 9) Node Summaries & Bounds (Plug-and-Play)

### 9.1 Node Summaries (precompute)

* **AABB**: per-dim $[L_d,U_d]$, and **count**.
* From bbox:
  $I_{r^2}(N)=[\min_{x\in N}\|x\|^2,\ \max_{x\in N}\|x\|^2]$
  (achieved at bbox corners w\.r.t. origin).

### 9.2 Query-Time (per $c$) cache

* **Projection interval** via bbox support:

  $$
  I_s(N) = \left[\min_{x\in N}\langle c,x\rangle,\ \max_{x\in N}\langle c,x\rangle\right].
  $$

  Compute in $O(d)$ by choosing $L_d$ vs $U_d$ per sign of $c_d$.

### 9.3 Bounds for Node Pair $(A,B)$

Let

$$
I_N = I_s(A)\ominus I_s(B)\ \ominus\ \tfrac12 I_{r^2}(A)\ \oplus\ \tfrac12 I_{r^2}(B),\quad
|I_N|=[\min|I_N|,\ \max|I_N|].
$$

Let

$$
D_{\min}=\text{minDist}(A.\text{bbox}, B.\text{bbox}),\quad
D_{\max}=\text{maxDist}(A.\text{bbox}, B.\text{bbox}).
$$

**Safe bounds over all pairs in $(A,B)$:**

$$
\boxed{\mathrm{LB}(A,B)=\frac{\min |I_N|}{D_{\max}+\varepsilon}},\qquad
\boxed{\mathrm{UB}(A,B)=\frac{\max |I_N|}{\max(D_{\min},\varepsilon)}}.
$$

* **Exclusion:** prune if $\mathrm{LB}\ge \text{best}$ (or $>\tau$ in threshold mode).
* **Subsumption / early-accept:** if $\mathrm{UB}\le \tau$ or update global best when minimizing.

### 9.4 Minimal Bound Routine (language-agnostic)

```pseudo
function NODE_BOUNDS(A, B, c, eps):
    (a_min, a_max) ← PROJ_INTERVAL(A.bbox, c)  # O(d)
    (b_min, b_max) ← PROJ_INTERVAL(B.bbox, c)

    # Numerator interval: Ia ⊖ Ib ⊖ 0.5*Ir2(A) ⊕ 0.5*Ir2(B)
    num_min ← (a_min - b_max) - 0.5*A.r2_max + 0.5*B.r2_min
    num_max ← (a_max - b_min) - 0.5*A.r2_min + 0.5*B.r2_max

    if num_min ≤ 0 ≤ num_max:
        num_abs_min ← 0
    else:
        num_abs_min ← min(|num_min|, |num_max|)
    num_abs_max ← max(|num_min|, |num_max|)

    dmin ← MIN_DIST_BOXES(A.bbox, B.bbox)     # O(d)
    dmax ← MAX_DIST_BOXES(A.bbox, B.bbox)     # O(d)

    LB ← num_abs_min / (dmax + eps)
    UB ← num_abs_max / max(dmin, eps)
    return (LB, UB)
```

The complexity of computing the Projection Interval is **`$O(d)$`**, where `$d$` is the number of dimensions.

It can be calculated very quickly at query-time by using the pre-computed **Axis-Aligned Bounding Box (AABB)** for the node.

-----

### \#\# How the `$O(d)$` Calculation Works

You do **not** need to iterate through every point inside the node. Instead, you can find the two corners of the node's AABB that give the absolute minimum and maximum possible dot products with `$c$`.

Let the AABB for a node `$N$` be defined by its minimum (`$L$`) and maximum (`$U$`) corner vectors, where `$L = [L_1, L_2, ..., L_d]$` and `$U = [U_1, U_2, ..., U_d]$`.

To find `$\min_{x \in N} \langle c, x \rangle$`, you construct a point `$x_{min}$` by choosing the coordinate for each dimension that makes the product `$c_k \cdot x_k$` as small as possible:

  * If `$c_k \ge 0$`, you want the smallest possible `$x_k$`, which is `$L_k$`.
  * If `$c_k < 0$`, you want the largest possible `$x_k$`, which is `$U_k$`, to make the product most negative.

The logic is symmetric for finding the maximum value.

#### **Pseudocode:**

```pseudo
function COMPUTE_PROJECTION_INTERVAL(AABB, c):
    d = number_of_dimensions
    min_projection = 0
    max_projection = 0

    for k from 1 to d:
        if c[k] >= 0:
            min_projection += c[k] * AABB.min_corner[k]  // Use L_k
            max_projection += c[k] * AABB.max_corner[k]  // Use U_k
        else:
            min_projection += c[k] * AABB.max_corner[k]  // Use U_k
            max_projection += c[k] * AABB.min_corner[k]  // Use L_k
            
    return (min_projection, max_projection)
```

This requires a single pass through the `$d$` dimensions, making the complexity `$O(d)$`. Because this is extremely fast, it's not a bottleneck and can be efficiently computed for each new center at query-time.

## 10) Dual-Tree BnB (Best-First, Non-Redundant)

```pseudo
function DualTreeBnB(root, c, eps):
    PQ   ← min-heap of (LB(root,root), root, root)
    best ← +∞
    seen ← set()  # to enforce non-redundant (unordered) node-pair visitation

    while PQ not empty:
        (lb, A, B) ← pop_min(PQ)
        key ← unordered_key(A,B)
        if key in seen: continue
        seen.add(key)

        if lb ≥ best: continue                # exclusion
        ub ← UB(A,B)
        if ub < best: best ← ub               # tighten anytime best

        if A.leaf and B.leaf:
            for i in A.points:
                for j in B.points:
                    if global_id(i) < global_id(j):  # non-redundant
                        best ← min(best, exact_d(i,j))
            continue

        # Decide which node to split (e.g., larger bbox volume or looser bound)
        split_A ← (not A.leaf) and (B.leaf or A.volume ≥ B.volume)
        if split_A:
            push(PQ, (LB(A.left,  B), A.left,  B))
            push(PQ, (LB(A.right, B), A.right, B))
        else:
            push(PQ, (LB(A, B.left),  A, B.left))
            push(PQ, (LB(A, B.right), A, B.right))

    return best
```

## 11) Random Baseline (Anytime)

```pseudo
function RandomSampling(X, budget_time, budget_calls, seed):
    RNG.seed(seed)
    best ← +∞
    for each checkpoint in time/call schedule:
        while time < checkpoint_time and calls < checkpoint_calls:
            (i,j) ← RNG.sample_unordered_pair(n)
            val ← exact_d(i,j)
            calls ← calls + 1
            if val < best: best ← val
        record A@B = min(1, d_star / best)
```

## 13) Runbook (Per Dataset × Center × Additivity)

1. **Build trees** (kd and ball) from $X$ with configured leaf size & splits; cache:

   * bbox $[L_d,U_d]$, count,
   * $I_{r^2}=[\min\|x\|^2,\max\|x\|^2]$ from bbox corners.
2. **Sample center $c$**; cache $I_s(N)$ for all nodes (per $c$).
3. **Compute $d^\star$** once using exact BnB (either tree).
4. **Time normalization:** run **dual kd-tree BnB** & **ball-tree BnB** to completion; repeat **$r$** times; set $T_{\max}$.
5. **Anytime logging:** for each method (including random), record best-so-far $d$ at all **time** and **calls** checkpoints; convert to **A\@B** via $d^\star$.
6. **Aggregation:** across runs, compute **median** and **95% bootstrap CI** per checkpoint.
7. **Plots:** generate the four requested figure types; save CSV/JSON of curves.

## 16) Correctness & Complexity Checks

* **Correctness on small $n$:** brute-force $\min d(i,j)$ equals BnB output.
* **Per node-pair bound:** $O(d)$ time with cached $I_s$; constant space.
* **Traversal cost:** data-dependent; expect **orders-of-magnitude fewer** leaf touches than $O(n^2)$ when bounds are tight.

---

## 17) Non-Redundancy & Edge Cases

* Enforce unordered pairs: **$i<j$** only; avoid visiting $(A,B)$ and $(B,A)$ twice (use node keys).
* Numerical stability: protect with $\varepsilon$ in denominators and when $D_{\min}\approx 0$.
* Degenerate or identical points: ensure denominator handling and pair de-duplication.

---

## 18) Expected Outcome (Hypothesis)

**Ball-tree BnB** attains **higher A\@B earlier** (time and calls), with a **widening gap** as $n$ increases and centrality difficulty grows, reflecting **tighter pruning** and **robustness**.
